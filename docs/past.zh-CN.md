# 一年，三个项目

这三个项目之间的联系，是我越来越关心一个研究想法如何面对数据、算力与协作。我在一年内依次探索了 Alex-Fin、BenjaminAgent 和量融智枢。下面记录问题与决策的变化，具体日期以各项目的源码和实验记录为准。

## Alex-Fin：选择模型，也理解模型的每一部分

Alex-Fin 从自适应资产配置出发，把多频率信息、资产图关系、混合专家和强化学习策略结合起来。论文稿报告的样本外年化收益率为 18.72%、年化夏普比率为 1.43、最大回撤幅度为 12.65%；项目仓库说明评价条件及稿件来源。

这项工作也让我看到了自己推进方式中的薄弱环节。我期待尽快得到结果，对模型各部分的理解却还不均衡。AutoDL 的算力成本压缩了探索时间。当架构、实现、评价和解释同时争夺有限的注意力时，研究便很难持续。

我希望带到下一项工作中的方法，是给每个组件配上能够回答的问题：它接收什么，输出什么，哪一个更简单的对照能检验它的贡献？这样，复杂架构才能变成我可以逐步解释和改进的对象。

## BenjaminAgent：把研究组织成工作流

BenjaminAgent 把问题推进到金融研究智能体：任务如何分解，候选因子如何生成，一次尝试的结果又如何成为下一次可用的记忆？现有工程以 DeerFlow 为基础，加入金融任务与 Qlib 扩展；公开讲解把设计与实际模块逐项对应。

部署选择也是学习的一部分。我曾继续使用 GPU 租赁环境，承载同时需要普通网页服务托管的工作。后来才逐步理解计算实例与普通云服务器承担的不同职责。资源规划因此需要分别考虑训练、批量评价与持续在线的服务。

## 量融智枢：让研究和产品相互连接

量融智枢连接了风险建模、带约束的组合目标、量子线路和研究工作台。现有材料包括产品源码、算法软件、执行过的 Notebook 与注册实验。硬件研究让编译和测量条件也进入了研究记录。

我承担实验设计、产品架构与模型架构设计。在暑期竞赛准备阶段，我没有紧密参与一线代码实现。因此，贡献记录分别说明设计、编码、部署和实验执行的职责。理解系统，也包括理解其他贡献者如何让它真正工作。

实验结果有改善，也有不足，这使下一步的问题更具体。编码一致性可以成立，某个量子组件仍可能逊于经典基线；硬件可行率也可能与理想线路有明显差异。[项目证据](https://github.com/Soros2040/Q-Fintelligence)将这些区别展示出来。

## 三个项目之间发生了什么变化

| 早先的问题 | 现在会增加的问题 |
| --- | --- |
| 这个架构能否表达想法？ | 哪个组件具有增量贡献的证据？ |
| 能否完成一次运行？ | 别人能否找到配置并解释结果？ |
| 能否租到足够算力？ | 哪些环节需要 GPU、普通服务器，哪些可以用 CPU 检查？ |
| 能否完成项目？ | 文档和职责能否支持后续协作？ |

我在第二与第三个项目之间接触 Datawhale，并在第三个项目期间开始贡献。具体社区贡献应通过公开链接和实际范围记录。下一步，是让自己的工作也能被其他人这样理解。
