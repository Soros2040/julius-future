# 项目介绍

Julius' future 将个人发起的学习和研究组织成其他人能够参与的开放成果。项目以问题为起点，把资料、方法、实验、解释和维护安排放进同一条工作流程。

## 面向谁

- 希望通过具体问题学习量子机器学习和研究方法的学习者。
- 愿意复现实验、检验假设并贡献代码或文档的研究参与者。
- 希望通过读书、复现和共同研究培养成员的开源社区与实验室。

## 四个相互连接的模块

| 模块 | 工作方式 | 可交付成果 |
| --- | --- | --- |
| 学习 | 从问题补齐前置知识，并进行练习 | 学习路线、概念说明、练习 |
| 研究 | 冻结假设、基线、预算和评价方法 | 实验方案、实现、结果与局限 |
| 写作 | 用自己的话解释证据与推理 | 研究笔记、技术文章、论文材料 |
| 成果管理 | 通过任务、审阅、版本和交接推进 | 任务记录、版本说明、维护手册 |

## 第一条研究主线

量子核方法依赖特征映射与线路选择。搜索候选线路可能消耗大量模拟或测量资源，有限 shots 与设备噪声又会改变候选排序。项目将研究这一具体瓶颈，再检验得到的表示能否服务于风险增强组合优化。

应用链路包括量子核自设计、局部量子消息线路、风险图聚合、风险参数到 QUBO/Ising 的转换，以及 QAOA 组合候选生成。各阶段使用独立基线和证据，逐步验证接口是否有效。

项目介绍中的方法是拟研究的方案；实验结论以公开的配置、结果与复核记录为依据。研究评价和教学评价分别记录：前者看问题是否被有效回答，后者看学习者能否理解与复现。

## 协作与持续维护

近期先完成最小可复现实验，再围绕经过验证的模块编写教程，并寻求 Datawhale 社区及实验室的反馈与协作。

长期维护依靠明确的模块负责人、第二位审阅者、可复现环境和交接记录。资源支持可包括算力、指导、共同维护和符合许可的授权合作。具体支持以各方实际约定为准，项目按季度回顾投入、使用价值与维护负担。

贡献通过 Issue 和 Pull Request 留下可追溯记录；署名依照实际贡献。后续研究论文的作者资格在研究启动时讨论，随贡献变化更新。
