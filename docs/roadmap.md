## 首批可认领任务

认领前先搜索现有 [Issues](https://github.com/Soros2040/julius-future/issues)。使用[任务模板](https://github.com/Soros2040/julius-future/issues/new?template=task.md)记录任务编号、拟处理范围、交付位置和预计时间；维护者确认后，本表补充 Issue、负责人及状态。

| 编号与任务 | 具体交付 | 验收条件 | 状态 / 负责人 / Issue |
| --- | --- | --- | --- |
| **T01 · 引用复核** | 选择研究方案中的一条有来源依据的陈述，在 Issue 提交下方复核记录；需要改文时同步更新 [references.md](../research/references.md) 和对应研究陈述 | 原句可定位；原始来源的题名、版本、章节或页码明确；支持程度有理由；修改建议可直接对应到原句；访问受限处如实记录 | 未认领 / 待认领 / 待建立 |
| **T02 · 经典基线公平性复核** | 从[研究方案](../research/quantum-research.md)的首个实验或下游评价中选一组量子与经典方法比较，在 Issue 提交条件清单，并提出对应段落修改 | 清单覆盖数据与划分、预处理与特征、调参范围、搜索与训练预算、指标与随机性；每项注明现有依据、待明确项及建议；列出适用的经典基线和选择理由 | 未认领 / 待认领 / 待建立 |
| **T03 · 前置概念说明** | 在[学习与写作指南](learning-and-writing.md#prerequisite-notes)的“前置概念说明”下增加一个完整小节，选量子核或时间外验证中的一个概念 | 写明读者问题、前置知识及研究用途；定义符号；提供一个可手算或可复核的最小例子、原始来源和一道自检题；审阅者可按材料说明检查答案 | 未认领 / 待认领 / 待建立 |

任务状态采用“未认领 → 进行中 → 待审阅 → 已完成”；存在阻碍时标注阻碍、所需信息和下一步。任务完成以验收与合并记录为准。

<a id="review-record"></a>

## 可复制的复核记录

可将以下模板复制到 Issue 或 PR。一次记录对应一条陈述；基线检查可按比较条件分别填写。原文摘录以必要范围为限，优先给出可定位的来源。

```markdown
### 复核记录

- 任务编号 / Issue：
- 记录者与日期：
- 仓库版本（commit）：
- 文档路径、章节及待核对原句：
- 原始来源（题名、作者、版本 / 日期、链接）：
- 原文位置（章节 / 页码 / 公式 / 表格）：
- 实际阅读范围与访问情况：
- 原文要点或必要摘录：
- 支持程度（充分支持 / 部分支持 / 不能支持 / 待核实）：
- 判断理由及适用条件：
- 修改建议（建议文字或具体下一步）：
- 建议修改的文件与位置：
- 尚待解决的问题：
- 审阅者与审阅记录（提交时可留空）：
- 关联 PR / 合并版本（提交时可留空）：
```

无法阅读全文或尚未读到相关位置时，支持程度填写“待核实”，并记录后续核对入口。一个题录链接用于找到来源，陈述的支持程度还需结合具体原文判断。

## 提交、审阅与登记

1. **提交**：贡献者在 Issue / PR 中给出交付物、复核记录和验收证据，任务进入“待审阅”。
2. **审阅**：审阅者按任务条件检查原文、比较条件或材料可理解性，记录结论与待改事项。实验结果需由另一位参与者尝试复现，才可标为“已复核”。
3. **合并与登记**：维护者确认验收后合并 PR，登记贡献者、版本、证据与状态，更新任务表；影响模块进度时同步首页。已经合并但尚缺独立复核的结果保留“待复核”。
4. **继续维护**：新问题关联原成果登记和版本，修改经审阅后追加记录。交接按[维护与交接](maintenance.md)执行。

详细提交要求见[贡献指南](../CONTRIBUTING.md)。
